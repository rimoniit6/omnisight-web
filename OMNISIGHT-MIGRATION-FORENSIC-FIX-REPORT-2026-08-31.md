# OMNISIGHT-MIGRATION-FORENSIC-FIX-REPORT-2026-08-31

## 1. Original P3018 Failure

```
Error: P3018
Migration: 20260827010000_agent_token_org_not_null
Database error code: 42703
Database error: column "organizationId" of relation "AgentToken" does not exist
```

The failing migration attempted `ALTER TABLE "AgentToken" ALTER COLUMN "organizationId" SET NOT NULL`, but the `organizationId` column never existed on the `AgentToken` table at that point in the migration chain.

## 2. Exact Root Cause

**Scenario 1 — Missing column creation in the initial migration.**

The initial migration `20260810105722_postgresql_initial` created the `AgentToken` table **without** the `organizationId` column. The schema was later updated to include `organizationId` on `AgentToken`, but **no migration was ever generated** to add this column. The migration `20260827010000_agent_token_org_not_null` was authored assuming the column already existed as nullable — but it was never created.

**Additionally**, three Prisma schema models had **zero corresponding migration**:
- `OrganizationMembership` — critical (used by seed, multi-org auth)
- `AudioRecording`
- `AudioTranscription`

These tables were in the schema but never created by any migration.

## 5. SQL/Migration Changes

### Modified: Initial Migration (`20260810105722`)
```sql
-- Added to AgentToken CREATE TABLE:
"organizationId" TEXT NOT NULL,

-- Added FK:
ALTER TABLE "AgentToken" ADD CONSTRAINT "AgentToken_organizationId_fkey"
  FOREIGN KEY ("organizationId") REFERENCES "Organization"("id")
  ON DELETE CASCADE ON UPDATE CASCADE;

-- Added index:
CREATE INDEX "AgentToken_organizationId_idx" ON "AgentToken"("organizationId");
```

### New: Migration `20260831074935_add_missing_tables`
- Creates `OrganizationMembership` table with unique constraint on `(userId, organizationId)`
- Creates `AudioRecording` and `AudioTranscription` tables
- Adds `UserSession.activeOrganizationId` column with FK
- Adds missing composite indexes on `Device` and `Screenshot`

## 6. Why the Fix is Safe

- **This is an unreleased, local-only migration chain.** No production database has ever run these migrations. The commit history shows the project was set up on 2026-08-18 and has only 14 commits on `main`.

- The new migration was generated by `prisma migrate dev --create-only` against the actual schema, ensuring correctness.
- All migration SQL is idempotent-safe (uses `IF NOT EXISTS` where applicable).
- No existing migration was broken or had its semantics changed.
